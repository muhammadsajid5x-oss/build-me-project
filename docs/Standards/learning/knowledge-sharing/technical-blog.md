# Introduction

Software development is more than writing code. A successful project requires clear architecture, engineering standards, documentation, automation, testing, and collaboration. During Sprint 3 of the Build Me project, my primary focus was to establish the engineering foundation that will support future feature development.

Rather than implementing new application features, this sprint focused on creating the systems, standards, and documentation that enable consistent software delivery. These efforts help ensure the project remains maintainable, scalable, and easy for new team members to understand and contribute to.

# Project Overview

Build Me is a modern full-stack web application developed using a monorepo architecture. The project follows a structured DevSecOps lifecycle and emphasizes reusable components, API-first development, documentation, and continuous improvement.

The technology stack includes:

- React
- TypeScript
- Vite
- Storybook
- Node.js
- Express
- Drizzle ORM
- Supabase PostgreSQL
- TurboRepo
- pnpm
- GitHub
- Vercel

This combination provides a scalable development environment suitable for modern web applications.

---

# Why I Chose This Architecture

One of the most important decisions was using a TurboRepo monorepo.

A monorepo allows multiple applications and shared packages to exist within a single repository. This improves code sharing, simplifies dependency management, and creates a consistent developer experience.

The project structure separates responsibilities into different areas:

- **apps/** for frontend and backend applications
- **packages/** for reusable UI components and shared code
- **docs/** for technical documentation
- **configuration files** for tooling and automation

This organization makes the project easier to maintain as it grows.

# What I Learned

This sprint reinforced several important engineering principles.

## Documentation Is Part of Development

Writing documentation is not separate from software development—it is an essential part of building maintainable systems.

Well-written documentation reduces onboarding time, improves collaboration, and preserves technical knowledge.

---

## Standards Improve Consistency

Engineering standards help teams make consistent technical decisions.

Without standards, different developers often solve similar problems in different ways, leading to unnecessary complexity.

---

## Automation Saves Time

Automating repetitive engineering tasks reduces manual effort and improves software quality.

Areas such as testing, deployment, and documentation can all benefit from automation.

---

## Reusable Assets Increase Productivity

Creating templates, checklists, and guides once allows the team to work faster in future sprints while maintaining consistent quality.

---

# Lessons Learned

Several lessons stood out during this sprint:

- Good documentation improves communication.
- Small reusable components are easier to maintain.
- Planning before development reduces rework.
- Continuous improvement should be part of every sprint.
- Engineering quality depends on consistent standards rather than individual effort.
